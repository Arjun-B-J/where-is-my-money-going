# Evaluations

How well the categoriser, the memory and the chat agent actually work, measured
against labelled data on one machine. Every table below is generated by
`wimmg eval-summary` from the JSON run records, never typed, and each run line names
the model digest and the dataset hash it was scored against. The reasoning behind
the harness is [DECISIONS.md §17](DECISIONS.md#17).

**Machine.** RTX 5090 Laptop GPU (24 GB), Intel Core Ultra 9 275HX, 32 GB RAM,
Windows 11, Ollama 0.34.4. Concurrency 4 unless stated. Latency is per model call,
after a warm-up call that loads the weights.

## Results

Five local models, all on Ollama 0.34.4, run on 2026-09-28 against the same labels.

**What the numbers say**

- **`gemma4:26b` stays the default.** It is the most accurate at categorising (91.0%) and,
  being a mixture-of-experts model with about 4B parameters active per token, faster per
  call (1.6 s) than any other model above 3B.
- **`qwen3.8:27b` is the most careful and the slowest large model.** It has the highest
  precision on auto-accepted rows (97.2%) and gets every refund right, but it abstains on
  14% of rows that have an answer and takes 2.7 times as long per call.
- **Rules before the model help weak models and hurt strong ones.** The 3B model goes from
  52.8% to 65.8% with rules in front, the 8B from 70.9% to 72.9%, while the three strong
  models lose 1.6 to 3.0 points: the rules are confidently wrong on rows a strong model
  gets right (Instamart is groceries, Amazon Prime is a subscription, a refund is not
  spending). That is why `LLM_FIRST` defaults to true.
- **Your corrections help every model, and no model copied a label onto a look-alike.**
  Repeat payees are 100% for all five because the first tier needs no model; the same
  payee paid a different way ranges from 21% to 79% and is where model quality shows.
- **Tools, not the model, do chat arithmetic.** The tool-calling agent answered 88% to
  100% of the questions across all five models, against 4% to 16% for the fixed summary.
  Even the 3B model gets 22 of 25.

**Not investigated.** `gemma4:12b`'s 12-second median call is out of line with its size
and with the 26B model's 1.6 s. The likeliest cause is a context-size setting pushing part
of the model onto the CPU on this machine, not the model itself, so its latency should
not be compared.

## What each suite measures

### Categorising: `golden_v1.jsonl`, 199 rows

Realistic Indian bank and card narrations, written to be hard rather than typical:

| Slice | n | What it tests |
|---|---|---|
| clear_merchant | 48 | A brand name in plain text |
| legal_entity | 35 | The merchant appears only as its registered company name (`BUNDL TECHNOLOGIES` is Swiggy) |
| gateway_masked | 18 | A payment-gateway prefix in front (`RAZ*`, `PYU*`, `BILLDESK*`) |
| structural | 27 | Salary, ATM codes such as `ATW-`, EMIs, card bills, SIPs, bank charges |
| credit | 12 | Refunds, cashback, interest, dividends: money in, never spending |
| person | 24 | Transfers to and from individuals, with and without a remark |
| opaque | 19 | Nothing in the narration says what the payment was for |
| ambiguous | 16 | More than one category is defensible; any of them counts |

The columns that matter most for this app:

- **Auto-accept precision** and **coverage**: rows at or above the review threshold
  (0.70) are trusted without a human looking. Precision is how often those rows are
  right; coverage is how many rows clear the bar.
- **Abstain recall** and **false abstain**: saying "uncategorized" is correct for an
  opaque payee and wrong for Swiggy. Both directions are measured.
- **ECE**: whether a stated confidence of 0.9 means right about nine times in ten.
- **Valid**: the share of calls that returned a usable, on-schema answer.

### Learning from corrections: `personal_v1.jsonl`, 34 scored rows

Twelve fictional regular payees (a landlord, a milkman, an auto driver, a tiffin
service...) each have two rows standing in for categories you set by hand. The
scored rows are:

| Slice | n | What it tests |
|---|---|---|
| repeat_payee | 12 | The same payee under the same UPI handle |
| payee_variant | 14 | The same payee paid differently: a new handle, IMPS or NEFT with no handle, a card payment at the same shop. Two rows abbreviate the name (`KISHORE K`), which the name check is known to miss |
| lookalike | 8 | A stranger with a similar name (`ZAKIR KHAN` is not `ZAKIR HUSSAIN`); inheriting a past label here is the error |

Arms: `llm` (the model alone), `lookup` (copy a past label for the same handle, no
model) and `llm+memory` (both tiers, as the pipeline runs them).

### Chat: `chat_v1.jsonl`, 25 questions

Asked against a throwaway database built from the synthetic generator (seed 42,
twelve months ending 2026-08-31, "today" fixed at 2026-08-31). Each expected figure
is computed at eval time by separate SQL, not by the agent's tools, so a tool bug
cannot grade itself. An answer is correct when every expected figure appears in it
(within ₹1 or 0.5%) and every expected name appears. Arms: `agent` (tool calling) and
`summary` (the fixed-summary prompt chat used before).

## Reproducing

```bash
ollama pull embeddinggemma            # for the memory suite
cd backend
wimmg eval --arm rules --arm llm --arm rules+llm --model <tag> [--model <tag> ...]
wimmg eval --suite personal --model <tag>
wimmg eval-chat --model <tag> --arm agent --arm summary
wimmg eval-summary eval_results/*.json
```

Records land in `backend/eval_results/` (gitignored); the ones behind this page are
listed under each table.

## Limits of these numbers

- **The labelled sets are stress sets written against the taxonomy text in
  `app/llm/prompts.py`, not samples of anyone's statements.** Per-slice accuracy is
  the useful signal; the overall figure is not a forecast for real data.
- **The labels are one careful reading, not a panel's.** Rows with two defensible
  answers list both.
- **Small sets.** One row is 0.5 percentage points of the categorising set and about
  3 points of the personal set, so differences of a few points are noise.
- **One machine, one run per configuration.** Latency will differ elsewhere; accuracy
  at temperature 0.1 still varies slightly between runs.
